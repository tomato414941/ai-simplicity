# ai-simplicity

AI の内部構造を利用者に管理させず、一つの連続した会話として提供するためのプロトタイプです。

この段階では、一つのサーバーインスタンスを一人の利用者として扱います。会話一覧、モデル選択、スレッド作成はありません。ブラウザを閉じたり別の端末から接続したりしても、同じバックエンドを使う限り同じ会話が続きます。

## 起動

Node.js 22 以上が必要です。

```sh
npm install
cp .env.example .env
```

`.env` に `OPENAI_API_KEY` を設定してから起動します。

```sh
set -a
source .env
set +a
npm start
```

ブラウザで <http://localhost:3000> を開きます。

## 設定

- `OPENAI_API_KEY`: 必須。Agents API の読み書きと Responses API の実行権限が必要
- `OPENAI_MODEL`: 新しいセッションで使用するモデル。初期値は `gpt-6-astra`
- `PORT`: HTTP ポート。初期値は `3000`
- `STATE_PATH`: セッション ID と表示履歴の保存先。初期値は `data/state.json`

API キーはブラウザへ渡さず、サーバーだけが保持します。ローカルの状態ファイルは Git の対象外です。

## エージェント

[OpenAI Agents API](https://developers.openai.com/api/docs/guides/agents-api/quickstart) と公式 JavaScript SDK を使います。エージェントの実行ループ、ツール実行、会話コンテキストの管理は OpenAI 側に任せています。

- Web 検索を `live` モードで有効化
- 外向き通信ができる OpenAI-hosted 環境で、必要に応じて HTTP 取得やコード実行
- 同じセッションを継続利用。アプリを再起動しても保存済み ID を再利用

コードはアプリのサーバーではなく OpenAI 側の隔離環境で実行されます。アプリの API キーや環境変数はその環境に渡しません。ブラウザのクリック操作、サイトへのログイン、個別サービスの認証連携はまだありません。モデル利用に加えて検索・実行環境の料金がかかります。

入力は一度に一件だけ受け付け、生成前に保存します。[公式 SDK のストリーム](https://developers.openai.com/api/docs/guides/agents-api/sessions/events)から受け取った途中の文章も保存し、画面は約2秒ごとに状態を取得します。上流の受信が止まった場合は、保存済みの実行結果を確認して同じ返答欄に反映します。確認処理では新しい生成を開始しません。

返答の進行状態と、現在その状態を確認できるかどうかは別に扱います。正常な生成待ちに時間上限は設けず、文章がまだ出ていなくても待機を続けます。ストリームにも生成時間を理由に切断する期限は設けません。

画面で状態を確認できなくなったときだけ、自動復旧の時間を数え始めます。連続して60秒確認できなければ自動確認を区切り、「もう一度確認」を表示します。正常な生成状態や結果を確認できたら計測を解除します。アプリとの通信が成功しても、上流の状態を確認できていなければ計測は継続します。60秒は復旧時の表示方針であり、生成の失敗判定やキャンセルには使いません。

生成の失敗を確認できた場合だけ「再試行」で新しい実行を始めます。送信の受け付け自体を確認できない場合は、端末に保存した同じ送信 ID で手動再送できます。サーバーは受け付け済み・完了済みの ID を再実行しません。

画面を閉じても開始済みの処理は続きます。開き直すとサーバーに残っている状態を確認します。送信中の入力・受信済みの文章と下書きは端末にも保存するため、一時的に接続できなくても保持されます。ブラウザの保存機能が利用できず、入力を保存できない場合は送信しません。

新しいジョブ基盤やクライアント向けストリームの再接続層は使いません。旧 API・旧状態形式への互換処理や履歴インポートはありません。

表示履歴と[実行環境内のファイル](https://developers.openai.com/api/docs/guides/agents-api/environments/openai-hosted#files-and-lifetime)の寿命は別です。実行環境は永続ストレージとして扱わず、ファイルのダウンロードや環境期限切れからの自動復旧はこのプロトタイプの対象外です。

外部への送信・購入・変更は明示的な依頼なしに行わないよう指示していますが、強制的な承認ゲートは未実装です。認証のない一人用プロトタイプなので、信頼できる私用ネットワークだけで利用し、インターネットへ公開しないでください。

## API

- `GET /api/messages`: `{ "messages": [...], "pending": null | {...}, "observation": "current" | "unavailable" }` を返す。必要なら実行結果を確認するが、生成は開始しない
- `POST /api/messages`: `{ "id": "送信ごとの一意なID", "text": "..." }` を保存し、`202` と現在の状態を返す。同じ ID の再送で重複実行しない
- `POST /api/retry`: `{ "id": "失敗した送信のID" }` を受け取り、失敗が確定した実行のみ再試行する
- `GET /api/health`: 稼働状態を返す

OpenAI 固有のセッション ID やイベント形式は、この API の内側に閉じ込めています。

`pending` は送信内容・途中の文章・生成状態（`processing` / `completed` / `failed`）を含みます。`completed` のまま残るのは、生成完了を確認済みで、本文の取得を待っている場合です。返答を保存できたら履歴に移し、`pending` を `null` にします。未解決の入力がある間、別の入力は受け付けません。

`observation` は今回必要な状態・結果を確認できたかを表します。通信の問題はこの確認状況にだけ反映し、保存済みの生成状態を変更しません。処理中と確認できた場合は、途中の文章の取得だけが失敗しても正常な待機を続けます。

## テスト

```sh
npm test
```

テストでは OpenAI API を呼びません。SDK のエラー受信、HTTP 応答の消失、再起動からの復旧、二重実行防止に加え、仮想時計で長時間推論・障害発生からの60秒・復旧による計測解除と表示文言を検証します。画面のテストは DOM のテスト用実装で動作し、ブラウザ操作はしません。
